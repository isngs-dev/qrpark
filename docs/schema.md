# Database schema

**Living document.** Read it before implementing anything that touches the
database. Update it in the same commit as any migration. If it and the code
disagree, one of them is wrong: say which rather than working around it.

Source of truth: `backend/prisma/schema.prisma` and
`backend/prisma/migrations/`. CI applies the migrations to an empty database
and fails if the result differs from `schema.prisma`.

Created: Sprint 1 (migration `0001_init`).

---

## Conventions

| Rule | Detail |
|---|---|
| Primary keys | `UUID`, generated by the application. Never sequential, never a credential |
| Names | Tables and columns `snake_case` in the database; Prisma maps them to camelCase (`@map`) |
| Money | `INTEGER`, always **kobo**. Never float, never decimal naira. Columns end `_kobo`. All amounts > 0 |
| Timestamps | `TIMESTAMPTZ(6)`, UTC, set by the **backend**. Shown in Africa/Lagos. A device never supplies a time |
| Site reference | Every table except `site` has `site_id NOT NULL` with a foreign key to `site` (tested) |
| Deletes | `ON DELETE RESTRICT` on every foreign key. Nothing operational is deleted; categories, gates and users are deactivated |
| Rules Prisma cannot express | CHECK constraints, the partial unique index and the two triggers (`ticket_requires_success_payment`, `audit_log_append_only`) are raw SQL at the end of `0001_init/migration.sql`. Each is named, and each has a test in `backend/src/db/constraints.lifecycle.test.ts` |
| The QR token | Stored only in `ticket.token`. No other table has a column for it; it is never logged |

## site_setting

One row per site. Edited in the Admin Portal; every change audited
(`SETTINGS_CHANGED`, with before and after).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| site_id | uuid | no | PK, FK → site. One row per site |
| display_name | text | no | `site_setting_display_name_check`: trimmed, 1–100 characters |
| validity_hours | integer | no | `site_setting_validity_hours_check`: 1–72. Copied onto each ticket at issue; a change never alters an issued ticket |
| receipt_org_name | text | yes | `site_setting_receipt_org_name_check`: 1–120 characters when set |
| receipt_contact_line | text | yes | `site_setting_receipt_contact_line_check`: 1–120 characters when set |
| updated_at | timestamptz | no | |

No logo column: receipt branding is an open question (known issue T2).

## ticket

Exists only for a payment Paystack confirmed.

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| payment_id | uuid | no | FK → payment (`ticket_payment_id_fkey`). UNIQUE (`ticket_payment_id_key`): one ticket per payment |
| token | text | no | The QR. UNIQUE (`ticket_token_key`). `ticket_token_check`: `^[A-Za-z0-9_-]{43}$` (32 random bytes, base64url) |
| ticket_number | text | no | UNIQUE (site_id, ticket_number). `ticket_ticket_number_check`: `XXXX-XXXX` from `ABCDEFGHJKMNPQRSTUVWXYZ23456789` (no 0/O, 1/I/L). Random, retried on collision. Not a credential |
| operator_id | uuid | no | FK → app_user (entry operator) |
| gate_id | uuid | no | FK → gate (entry gate) |
| category_name | text | no | Snapshot |
| amount_kobo | integer | no | Snapshot. > 0 |
| customer_name | text | yes | 1–100 characters when set |
| payment_reference | text | no | Copy of `payment.reference` |
| paid_at | timestamptz | no | = `payment.paid_at` |
| issued_at | timestamptz | no | default `now()` |
| validity_hours | integer | no | Snapshot of the setting. 1–72 |
| valid_until | timestamptz | no | `ticket_valid_until_check`: `= paid_at + validity_hours hours` |
| status | ticket_status | no | default ACTIVE |
| used_at | timestamptz | yes | `ticket_used_before_expiry_check`: `<= valid_until` |
| used_gate_id | uuid | yes | FK → gate |
| used_by_id | uuid | yes | FK → app_user |
| created_at, updated_at | timestamptz | no | |

**Only for a SUCCESS payment.** The trigger `ticket_requires_success_payment`
(`BEFORE INSERT ON ticket`, raw SQL) reads the payment `FOR SHARE` and raises
unless its status is SUCCESS. `FOR SHARE` holds the payment row until the
inserting transaction ends, so its status cannot change between the check and
the insert. It checks INSERT only, on purpose: a payment's status may change
later (Phase 2 refunds and cancellations) without touching its ticket. A
composite foreign key was used first and replaced, because `ON UPDATE
RESTRICT` froze a payment at SUCCESS forever.

`ticket_used_fields_check`: `used_at`, `used_gate_id` and `used_by_id` are
set together, and only when status is USED.

Index: `(site_id, status, valid_until)`.

## scan_event

Every check and exit scan. Never stores the scanned text: a code that matched
no ticket leaves no trace of itself (tested: the table has no such column).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| ticket_id | uuid | yes | FK → ticket. `scan_event_ticket_by_result_check`: null if and only if the result is NOT_FOUND or INVALID_QR |
| kind | scan_kind | no | |
| result | scan_result | no | `scan_event_result_by_kind_check`: ACTIVE only for CHECK, VALID only for EXIT |
| gate_id | uuid | no | FK → gate |
| operator_id | uuid | no | FK → app_user |
| device_ref | text | no | The app's installation id. Record only, never trusted. `scan_event_device_ref_check`: 1–64 characters |
| occurred_at | timestamptz | no | default `now()`, backend time |

Indexes: `(site_id, occurred_at)`, `(ticket_id)`.

## audit_log

Who did what, when, to which record. **Append-only:** the trigger
`audit_log_append_only` raises on every UPDATE and DELETE (tested). TRUNCATE
is not covered: the deployed database user must not hold TRUNCATE (known issue L2).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| actor_id | uuid | no | FK → app_user. Never null |
| action | audit_action | no | |
| target_type | text | no | `site_setting`, `vehicle_category`, `gate`, `app_user`, `ticket` |
| target_id | text | no | |
| detail | jsonb | yes | Before and after values. Never a password, a hash or a token |
| occurred_at | timestamptz | no | default `now()` |

Indexes: `(site_id, occurred_at)`, `(site_id, target_type, target_id)`.

# Database schema

**Living document.** Read it before implementing anything that touches the
database. Update it in the same commit as any migration. If it and the code
disagree, one of them is wrong: say which rather than working around it.

Source of truth: `backend/prisma/schema.prisma` and
`backend/prisma/migrations/`. CI applies the migrations to an empty database
and fails if the result differs from `schema.prisma`.

Created: Sprint 1 (`0001_init`). Last change: Sprint 4b (`0004_payment_cancelled`):
the audit action `PAYMENT_CANCELLED`. Before that, Sprint R (`0003_booth_flow`),
the flow of 2026-11-07: entry creates an UNPAID ticket, a payment booth takes
cash or card, exit requires PAID.

---

## Conventions

| Rule | Detail |
|---|---|
| Primary keys | `UUID`, generated by the application. Never sequential, never a credential |
| Names | Tables and columns `snake_case` in the database; Prisma maps them to camelCase (`@map`) |
| Money | `INTEGER`, always **kobo**. Never float, never decimal naira. Columns end `_kobo`. All amounts > 0 |
| Timestamps | `TIMESTAMPTZ(6)`, UTC, set by the **backend or the database**. Shown in Africa/Lagos. A device never supplies a time. `ticket.issued_at` and `valid_until` are set by the database |
| Site reference | Every table except `site` has `site_id NOT NULL` with a foreign key to `site` (tested) |
| Foreign keys | A plain foreign key, written "FK → table" below, is named `<table>_<column>_fkey` (Prisma's naming). The two composite keys are named in full |
| Deletes | `ON DELETE RESTRICT` on every foreign key. Nothing operational is deleted: categories and locations are deactivated, accounts soft-deleted |
| Rules Prisma cannot express | CHECK constraints, partial unique indexes, `lagos_day_end()` and the triggers are raw SQL in the migrations (`0001_init`, `0003_booth_flow`). Each is named; each has a test in `backend/src/db/constraints.lifecycle.test.ts` or `backend/src/db/tickets-payments.lifecycle.test.ts` |
| The QR token | Stored only in `ticket.token`. No other table has a column for it; it is never logged |
| **The freeze** | A SUCCESS or DUPLICATE payment never changes status; a PAID ticket never goes back to UNPAID; a VALIDATED ticket never goes back. Deliberate (no refunds, reversals or overrides in release 1). Lifted only by a future migration if Phase 2 adds refunds |

## Functions

| Function | What |
|---|---|
| `lagos_day_end(ts timestamptz)` | The start of the next day in Africa/Lagos (UTC+1, no daylight saving) after `ts`. A ticket issued at 23:59:59 Lagos is valid for one second; at 00:00 Lagos it is a new day. Tested at fixed instants |

## site

One row per deployment.

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| code | text | no | UNIQUE (`site_code_key`). Matches `SITE_CODE` in the environment |
| created_at | timestamptz | no | default `now()` |

## site_setting

One row per site. Edited in the Admin Portal; every change audited
(`SETTINGS_CHANGED`, with before and after).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| site_id | uuid | no | PK, FK → site. One row per site |
| display_name | text | no | `site_setting_display_name_check`: trimmed, 1–100 characters |
| payment_window_minutes | integer | no | default 5. `site_setting_payment_window_minutes_check`: 1–30. How long a PENDING card payment blocks its operator before it is ABANDONED (after a Paystack check) |
| receipt_org_name | text | yes | The ticket's brand line. `site_setting_receipt_org_name_check`: 1–120 characters when set (else the display name is printed) |
| receipt_contact_line | text | yes | The line beneath it. `site_setting_receipt_contact_line_check`: 1–120 characters when set |
| updated_at | timestamptz | no | |

There is no validity setting: a ticket is valid on its day of issue
(`validity_hours` was dropped in 0003).

## gate (a location)

An entry gate, a payment booth or an exit gate. The table keeps the name

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| code | text | no | UNIQUE (site_id, code). `gate_code_check`: `^[A-Z][A-Z0-9_]{0,31}$`. Never changes |
| name | text | no | |
| direction | gate_direction | no | `ENTRY`, `EXIT` or `BOOTH`. Never changes: operators are assigned by it |
| is_active | boolean | no | default true |
| created_at, updated_at | timestamptz | no | |

## app_user

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| username | text | no | `app_user_username_check`: `^[a-z0-9._-]{3,32}$`. Unique per site **among live accounts** (`app_user_live_username_key`, partial: `WHERE deleted_at IS NULL`), so a deleted account's username can be reused |
| name | text | no | Kept after deletion, so reports still name the operator |
| password_hash | text | no | Argon2id. Never returned, never logged |
| role | user_role | no | One job per account |
| gate_id | uuid | yes | FK → gate. `app_user_gate_by_role_check`: null for ADMIN, required for an operator |
| token_version | integer | no | default 0, `app_user_token_version_check`: `>= 0`. Raised by logout, deactivation, deletion, a role or gate change and a password reset; a token with an older value is refused |
| is_active | boolean | no | default true |
| deleted_at | timestamptz | yes | Soft delete: hidden, cannot sign in, history kept. `app_user_deleted_is_inactive_check`: a deleted account is inactive |
| created_at, updated_at | timestamptz | no | |

Enforced in code, not the database: the location's kind matches the job
(ENTRY for an entry operator, BOOTH for a payment operator, EXIT for an exit
operator), and it is in service when assigned.

Prisma has no `@@unique` on (site_id, username) any more: it cannot express a
partial index, so lookups use `findFirst({ where: { siteId, username,
deletedAt: null } })`, and `migrate diff` does not see the index (as with the
other partial indexes).

## ticket

Created at entry, UNPAID. One per vehicle visit; the same QR from entry to
exit.

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| idempotency_key | text | no | UNIQUE (`ticket_idempotency_key_key`). From the entry app, one per attempt: a repeated tap returns the same ticket. `ticket_idempotency_key_check`: 1–100 characters |
| token | text | no | The QR. UNIQUE (`ticket_token_key`). `ticket_token_check`: `^[A-Za-z0-9_-]{43}$` (32 random bytes, base64url) |
| ticket_number | text | no | UNIQUE (site_id, ticket_number). `ticket_ticket_number_check`: `XXXX-XXXX` from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`. Not a credential |
| operator_id | uuid | no | FK → app_user (entry operator) |
| gate_id | uuid | no | FK → gate (entry gate) |
| device_ref | text | no | The entry app's installation id. `ticket_device_ref_check`: 1–64 characters |
| category_id | uuid | no | FK → vehicle_category |
| category_code, category_name | text | no | Snapshot at creation |
| fee_kobo | integer | no | The fee snapshot: the category's price at creation. `ticket_fee_kobo_check`: > 0 |
| issued_at | timestamptz | no | default `now()`, set by the database. The API never sets it; only raw SQL (tests, the Sprint 6 run) inserts an earlier day |
| valid_until | timestamptz | no | **Always** `lagos_day_end(issued_at)`, set by `ticket_insert_guard` whatever the insert says. Valid while `now() < valid_until` |
| payment_status | ticket_payment_status | no | default UNPAID |
| paid_payment_id | uuid | yes | UNIQUE. The SUCCESS payment that made it PAID |
| paid_at | timestamptz | yes | Backend time it became PAID |
| validation_status | ticket_validation_status | no | default NOT_VALIDATED |
| validated_at | timestamptz | yes | Database time of the exit validation |
| validated_gate_id | uuid | yes | FK → gate (exit gate) |
| validated_by_id | uuid | yes | FK → app_user (exit operator) |
| created_at, updated_at | timestamptz | no | |

**PAID only through a SUCCESS payment of its own (THE TOP RULE, in the
database):**
- `ticket_paid_payment_id_id_fkey`: (paid_payment_id, id) → payment (id,
  ticket_id), `ON UPDATE RESTRICT`: the paying payment belongs to this ticket.
- `ticket_paid_iff_payment_check`: PAID exactly when `paid_payment_id` is set,
  and `paid_at` with it.
- `ticket_guard` (BEFORE UPDATE): on UNPAID → PAID, the payment must be SUCCESS,
  read `FOR SHARE`.

**VALIDATED only when PAID:** `ticket_validated_requires_paid_check`.
`ticket_validated_fields_check`: `validated_at`, `validated_gate_id` and
`validated_by_id` are set together, and only when VALIDATED.
`ticket_validated_before_expiry_check`: `validated_at < valid_until`.

**`ticket_insert_guard`** (BEFORE INSERT): a new ticket is UNPAID and
NOT_VALIDATED; `issued_at` defaults to `now()`; `valid_until` :=
`lagos_day_end(issued_at)`.

**`ticket_guard`** (BEFORE UPDATE), besides PAID:
- never change: `token`, `ticket_number`, `fee_kobo`, `category_id`,
  `category_code`, `category_name`, `issued_at`, `valid_until`,
  `idempotency_key`, `site_id`, `operator_id`, `gate_id`, `device_ref`;
- never go back: PAID → UNPAID, VALIDATED → NOT_VALIDATED; `paid_payment_id`,
  `paid_at` and the `validated_*` columns never change once set (the freeze).

Indexes: `(id, fee_kobo)` UNIQUE (target of the payment's key),
`(site_id, issued_at)`, `(site_id, payment_status, validation_status,
valid_until)`.

## payment

One row per payment attempt at a booth; at most one SUCCESS per ticket.

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| ticket_id | uuid | no | The ticket paid for |
| amount_kobo | integer | no | `payment_amount_kobo_check`: > 0. **Equals the ticket's fee snapshot**: (ticket_id, amount_kobo) → ticket (id, fee_kobo) (`payment_ticket_id_amount_kobo_fkey`) |
| method | payment_method | no | CASH or CARD |
| reference | text | no | UNIQUE (`payment_reference_key`). Ours, for cash too; for a card also Paystack's (the webhook idempotency key). `payment_reference_check`: 1–100 characters |
| idempotency_key | text | no | UNIQUE (`payment_idempotency_key_key`). From the booth app, one per attempt. `payment_idempotency_key_check`: 1–100 characters |
| operator_id | uuid | no | FK → app_user (payment operator) |
| gate_id | uuid | no | FK → gate (booth) |
| device_ref | text | no | The booth app's installation id. `payment_device_ref_check`: 1–64 characters |
| status | payment_status | no | default PENDING |
| authorization_url, access_code | text | yes | Card only: Paystack's checkout. Returned to the operator only while PENDING. Never logged |
| paystack_event | jsonb | yes | Card only: the last verified Paystack payload, with `authorization.authorization_code` removed. Never logged |
| paid_at | timestamptz | yes | Backend time when SUCCESS was recorded. `payment_paid_at_iff_success_check`: set if and only if SUCCESS |
| paystack_paid_at | timestamptz | yes | Card only: Paystack's own paid time. Reconciliation only, never used for validity |
| created_at, updated_at | timestamptz | no | |

Rules:
- `payment_one_success_per_ticket`: `UNIQUE (ticket_id) WHERE status = 'SUCCESS'`.
- `payment_one_pending_per_ticket`: `UNIQUE (ticket_id) WHERE status = 'PENDING'`.
- `payment_one_pending_per_operator` (from 0001): `UNIQUE (operator_id) WHERE status = 'PENDING'`.
- `payment_cash_check`: a cash payment is SUCCESS and carries no Paystack field.
- `payment_duplicate_check`: DUPLICATE is a card status and keeps Paystack's payload.
- `payment_guard` (BEFORE UPDATE): never change `ticket_id`, `amount_kobo`,
  `method`, `reference`, `idempotency_key`, `operator_id`, `gate_id`,
  `device_ref`, `site_id`; a SUCCESS or DUPLICATE payment never changes status
  (the freeze). A late answer stays possible: PENDING, FAILED or ABANDONED may
  still become SUCCESS or DUPLICATE.

Indexes: `(id, ticket_id)` UNIQUE (target of the ticket's key), `(ticket_id)`,
`(site_id, status)`.

## scan_event

Every check and exit scan. Never stores the scanned text: a code that matched
no ticket leaves no trace of itself (tested: the table has no such column).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| ticket_id | uuid | yes | FK → ticket. `scan_event_ticket_by_result_check`: null if and only if the result is NOT_FOUND or INVALID_QR |
| kind | scan_kind | no | |
| result | scan_result | no | `scan_event_result_by_kind_check`: ACTIVE only for CHECK, VALID only for EXIT; PAYMENT_REQUIRED, ALREADY_USED, EXPIRED, NOT_FOUND and INVALID_QR for either |
| gate_id | uuid | no | FK → gate (where the scan happened) |
| operator_id | uuid | no | FK → app_user |
| device_ref | text | no | The app's installation id, from the `X-Device-Id` header. Record only, never trusted. `scan_event_device_ref_check`: 1–64 characters |
| occurred_at | timestamptz | no | default `now()`, database time |

A VALID row is written in the same transaction as the closing `UPDATE
ticket`, so its `occurred_at` equals the ticket's `validated_at`.

Indexes: `(site_id, occurred_at)`, `(ticket_id)`.

## audit_log

Who did what, when, to which record. **Append-only:** the trigger
`audit_log_append_only` raises on every UPDATE and DELETE (tested). TRUNCATE
is not covered: the deployed database user must not hold TRUNCATE (known
issue L2).

| Column | Type | Null | Constraint / note |
|---|---|---|---|
| id | uuid | no | PK |
| site_id | uuid | no | FK → site |
| actor_id | uuid | yes | FK → app_user. Null **only** for `LOGIN_THROTTLED` (nobody is signed in when a sign-in block starts): CHECK `audit_log_actor_required_check` (`actor_id IS NOT NULL OR action::text = 'LOGIN_THROTTLED'`), 0005 |
| action | audit_action | no | |
| target_type | text | no | `site_setting`, `vehicle_category`, `gate`, `app_user`, `ticket`, `payment`; for `LOGIN_THROTTLED`: `user` (the account, when the username is one) or `login` (target_id `-`) |
| target_id | text | no | |
| detail | jsonb | yes | Before and after values. Never a password, a hash or a token |
| occurred_at | timestamptz | no | default `now()` |

Ticket creation, payments and exit validation are recorded in their own rows
(ticket, payment, scan_event, each with operator, location, device and time);
the audit log carries cash confirmations, reprints, account changes and
configuration changes.

Indexes: `(site_id, occurred_at)`, `(site_id, target_type, target_id)`.

## Migrations

| Migration | Sprint | What |
|---|---|---|
| `0001_init` | 1 | All nine tables, the CHECKs, `payment_one_pending_per_operator`, the `audit_log_append_only` trigger (and the ticket→payment trigger, dropped in 0003) |
| `0002_payment_window` | 2 | `site_setting.payment_window_minutes` (default 5, CHECK 1–30) |
| `0003_booth_flow` | R | The booth flow. Refuses to run over existing ticket or payment rows (no conversion; reset and re-seed). Ticket: payment and validation status, fee snapshot, category, device, idempotency key, `issued_at` / `valid_until` by the database; `customer_name`, `validity_hours`, `payment_id`, `payment_reference` dropped. Payment: `ticket_id`, method, device; amount equals the fee; one SUCCESS / one PENDING per ticket. `lagos_day_end()`, `ticket_insert_guard`, `ticket_guard`, `payment_guard`. Roles and kinds: PAYMENT_OPERATOR, BOOTH; DUPLICATE; PAYMENT_REQUIRED; USER_DELETED, PAYMENT_CASH_CONFIRMED. `app_user.deleted_at` with a username unique among live accounts. `site_setting.validity_hours` dropped |
| `0004_payment_cancelled` | 4b | `ALTER TYPE audit_action ADD VALUE 'PAYMENT_CANCELLED'`, for `POST /payments/:id/cancel`. Needed because `audit_action` is a Postgres enum. Nothing else changes: a cancelled payment is `ABANDONED`, and the audit row holds the operator and whether it was forced. Adds a value only, so it runs over existing data unchanged |
| `0005_login_throttled` | H1 | `ADD VALUE 'LOGIN_THROTTLED'`; `audit_log.actor_id` nullable, with `audit_log_actor_required_check` keeping it required for every other action (compares the action's text, so the new value is not used in the transaction that adds it). Runs over existing rows unchanged (dev copy: row counts identical before and after) |
